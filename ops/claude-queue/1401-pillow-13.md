# 1401 The bot moves to Pillow 13.0.0 (Python floor 3.11)

**Not run yet.**

- **Lane:** Codex (GitHub)

- **Channel:** VPS (bot only). No gamemode, launcher, installer or records change.
- **Needs first:** nothing

## Run
From the shipping machine (One), in a fresh worktree at origin/main (ecbe5c62 or later). The script puts the bot on the VPS box itself:

    .\scripts\deploy\Install-Bot.ps1 -NoToken

It must be the FULL run. `-CodeOnly` does not install libraries, so it would send the new `bot\requirements.txt` and leave Pillow 12.3.0 in `py-libs`.

Order: only this one step. It can go before or after any other queued deploy; it touches only the bot.

## Check afterwards
- Install-Bot finishes without a pip error and reports Pillow 13.0.0 installed from the hash-pinned `requirements.txt`.
- `py-libs` on the VPS holds `pillow-13.0.0.dist-info` and no `pillow-12.3.0.dist-info`.
- The bot service is running and bot.log shows a clean start (no ImportError, no `_pyguard` refusal; the VPS Python is 3.12.10, above the new 3.11 floor).
- A member join (or `redraw.py` on a test member) posts a join card that looks the same as before.

## Risks and how to put it back
- A full Install-Bot restarts the bot: about a minute with no bot.
- If the bot does not start on the new libraries, the full run puts the old `py-libs` back by itself.
- By hand: `.\scripts\deploy\Install-Bot.ps1 -PutBack` puts back the code the last run replaced, with the `py-libs` beside it (step 3 of the script: the swap puts the libraries back with the code).
- Text on the join card: the Windows wheels already used HarfBuzz, so rendering should not move. The harness compares cards by closeness and passed (test-join-card 42/0) on One under Python 3.12.10.
- No Pillow API that 13.0.0 removed or changed is used by `card.py`, `make-join-card.py` or the harnesses.
