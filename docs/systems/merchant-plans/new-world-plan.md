## Measured cause

`createPrivateEconomyLedger.load` in the NPC MERCHANT PURSES block currently interprets absence of both merchant-ledger.json and merchant-ledger.initialized as a new installation. It writes null entries, and prepareState later grants250 gold to each active null entry. If an existing world's ledger and marker are lost together, an ordinary restart can therefore recreate balances. The historical-manifest and conservation prerequisites do not remove this inference.

1. Merchant runtime load must require an existing ledger and initialization marker before any write, including a native durable rewrite. Missing or corrupt evidence stops service and preserves remaining files. It never creates or repairs a merchant world. The separate dungeon-rewards behavior is outside this slice and stays unchanged.
2. Extract the existing private economy storage factory into a standalone server module, embedded by the existing gamemode generator so native temporary-directory hot reload remains self-contained. Preserve its private-path checks, native durable acknowledgement, checksum and namespace semantics. Retain global wrapper functions for existing callers and fixtures. Share the historical/active manifest helper with the initializer rather than duplicating its rules.
3. Add an explicit offline merchant initializer, invoked only for a separately authorized new world. Its CLI reads a settings file and the committed NPC population catalogue, requires an explicit new-world authorization ID and channel matching settings, and emits no settings contents. No restart, repair, Scan/Fix, installation or deploy script calls it automatically.
4. Before writing, validate the full historical/active manifest, authorization and private path outside served resources. Refuse if any ledger, initialization marker, pending temp file or initialization lock already exists. Never use this tool to recover an existing world or remove partial evidence.
