## The existing character problem (verified)

Measured in server.log, one tester, one existing character (OnlyChromes, all of tonight's connections were his or yours):

- After the 01:00 Deploy-Server process restart, "Loading character ff000015" was followed within the same millisecond by the server streaming the world around him (dozens of grid lines for WhiterunWorld) and normal play.
- After every kick from a restart countdown while the server process stayed up (00:29 for 1.1.40, 01:07 for 1.1.41), the identical login line was followed by nothing at all. 13 of 13 reconnects, 82 to 450 seconds each, not one hit, death or hoster change, then a disconnect. He reported "all of the NPCs are gone". Several of those were fresh game launches, so the broken state is on the server-side actor, and only a server process restart cleared it.
- Fresh characters (new actor) worked every time.

So a kick with no process restart behind it leaves that character's actor unable to get the world again. The re-attach path is `PartOne::SetUserActor` in the SkyMP server (skymp5-server/cpp/server_guest_lib/PartOne.cpp): it clears the hoster, calls `UnsubscribeFromAll`, `RemoveFromGridAndUnsubscribeAll`, then `ForceSubscriptionsUpdate`. Upstream's own comment on those lines says it is not covered by tests and that getting it wrong means "players will not be able to interact with items in the same cell after reconnecting". The subscription code reads as if it should re-send everything, so whether the server fails to send or the client fails to apply, I could not settle from source and logs alone. What would settle it: a `skyrim-platform.log` from a kick-reconnect, which shows whether createActor messages arrived. Tonight's change removes the trigger for the common case (launcher updates); since 1.1.41 the launcher closes the game itself five minutes after seeing an update, so the server kick was redundant there anyway. The real fix belongs in the C++ re-attach.

His characters ff000011 and ff000015 should work again now, because the 02:29 Deploy-Server restart reloaded every actor fresh.

## Bugs, most severe first

### Launcher

1. (verified) Shell.cs:228-238. Startup runs `Swap.Restore()`, `Keep.TakeNote()` and `Keep.Unpark()` with no check that this build's Skyrim is running. If the launcher was killed mid-session (Windows did that three times on 16 Sep per Waiting.cs) and reopened, the junctions come off under the running game so the rest of that session writes into the real Windows folders, and other servers' parked plugins are moved back into Data\Platform\Plugins while SkyrimPlatform hot-reloads them, the exact "two servers on screen" mixing Hold was written to prevent. Two independent passes found this. Fix: if `Checks.GameRunning()` at startup, set `playing = true`, re-take Hold, and skip Restore, TakeNote and Unpark; the exit tick already does them correctly.

2. (verified) Updater.cs:393-395. delete.txt paths are fenced before normalisation: `Path.Combine(Paths.Game, line)` then `Inside(target, Paths.Game)` with no `GetFullPath`, so a line like `..\..\Profile\x` starts with the game path string, passes the fence, and `File.Delete` resolves the `..` and deletes outside the game folder. Packs come from your own repo, so this is a typo away, not an attacker away, but it is a delete outside the fence. Fix: `GetFullPath` before `Inside`, as the entries loop at 423 already does.

3. (verified) Creation.cs:679-689. The Discord ticket, which Discord.cs calls as good as the server password, is sent in cleartext HTTP in the /choose body to the voice port, and the voice service never reads it (voice-server.js checks only profileId). Anyone on path can capture a credential that the site's join endpoint accepts. Fix: stop sending `ticket` from Send; if /choose needs identity, go through the HTTPS site.

4. (likely) Shell.cs:1133-1143 with Shell.cs:3094. After the game is closed for an update, `DrawStatus()` runs with `updatePending` still false, so Play is live during the follow-up fetch, and Play() never checks `updatePending`, `collectionBarUp` or `ownGameBusy`. A Play pressed in that window can start the game on top of a half-extracted pack. Fix: set `updatePending = true` in the closed branch before `CheckUpdatesBackground(true)`, and guard Play() on those three flags.

5. (likely) Shell.cs:3366-3383, 3611. Only `btnPlay` is disabled during the Door check; the slot cards' Play, Make and Delete stay live and StartAs has no in-flight guard. A double-click on a slot's Play runs the Door check twice and both callbacks call StartAs, so the game is started, killed as "stuck", and started again. Fix: a static `starting` flag in StartAs cleared in onDone, and disable `charBar` while the check is out.

6. (likely) Shell.cs:1082-1084, 3857. An update noticed during play is forgotten if the person quits before the five minutes run out, and `CheckUpdatesInPlay` resets the clock whenever the check returns "not due", which is also what a thrown check (GitHub 403 rate limit, 60 anonymous calls per hour per IP) looks like. Two people on one connection checking every two minutes can restart the clock forever. Fix: keep a separate `failed` flag; only reset `updateSeenAt` on a real "no update".

7. (verified) Shell.cs:961-974. The Fix button has no `Checks.GameRunning()` guard, unlike PackAction, RunDowngrade and StartOwnGame. With the game up, the plugin list Fix writes is rewritten by Skyrim on exit and the plugin fetch writes into Data under a live session. Fix: refuse with "Close Skyrim first."

8. (likely) Updater.cs:557-649. RemovePack never calls `Keep.Forget`, so a removed optional pack comes back: Install kept a copy of every Data\Platform file it wrote under Profile\Keep, RemovePack deletes the live file but not the kept copy, and `Keep.Restore` puts it straight back at the next Play. Fix: collect the removed `game\` rels and call `Keep.Forget`; on an own-folder install also remove them from the Steam copy.

9. (likely) Swap.cs:43 with Junction.cs:83-86 and Swap.cs:106-110. One failed junction creation orphans the person's real My Games or LocalAppData folder: Create makes the directory, Set fails, Apply throws, Restore sees `win` exists as an empty real folder and never moves `.st-backup` back; the next Apply renames the backup to `.st-backup-<stamp>` and nothing restores that name. Fix: in Junction.Create delete the directory it made when Set fails; in Restore, when `win` is an empty non-link folder and `bak` exists, delete `win` and move `bak` back.

10. (likely) Updater.cs:661-673 and Shell.cs:4028-4033. The self-update batch waits a fixed two seconds then `move /y`. The Closing path runs Swap.Restore, Hold.Release, Keep.Unpark and SkyMp.Stop (up to 5 s), so the move can hit a still-running exe, fail silently, `start` relaunches the old exe, and the next check offers the same update again in a loop. Two passes found this. Fix: loop the move until it succeeds, as Uninstall.Finish already does with tasklist.

11. (verified) Voice.cs:715-716. The 100 ms loop clears `lastStatusLine` before every `PublishStatus`, so two copies of voice-status.txt (one inside the game folder) are rewritten ten times a second for the launcher's whole lifetime, game running or not. Fix: keep the change check and republish on a 2 s timer.

12. (likely) Chars.cs:507-523 is fixed tonight; related and still open: AutoJoin.SetProfileId's return value is ignored at Chars.cs (Use), so if the settings file is read-only or stores the id as a quoted string, the game connects with the previous slot's id while everything else uses the new one. Fix: after SetProfileId, require `GetProfileId() == id` or stop before Play.

13. (likely) Verify.cs:395 (mine, tonight) and Verify.cs:470 (DeployPersonal, older). Both write through a hard link. On an own-folder install Root\Game\Data\X.esp, the Steam copy and Vortex's staging file are one inode, so the write changes the Nexus mod inside Vortex's staging, which other Vortex profiles for Skyrim (another server's collection) share. For a person who only plays Thornswood this is the persistent fix and Vortex sees no conflict; for a person with two SkyMP servers it puts our build of the plugin into the other one. The alternative, `OwnGame.Unshare(dest)` before writing, keeps it to our folder but leaves the wrong bytes in staging, and the next Vortex deploy asks to put them back. Your call which side of that you want; it is one line either way.

14. (likely) Voice.cs:551-554 with the page. Reconfigure posts a config on every Play and the page opens a new WebSocket without closing the old one; the voice server registers a new peer per join with no dedupe by profile. A second Play in one launcher session leaves a ghost peer on the roster announcing the previous slot's position. Fix: skip the Post when host, port and profile match the last one; close the old socket first in the page.

15. (likely) Account.cs:66, 100. The voice server in the repo has no /whoami or /claim route, so Whoami is always empty, Claim never lands, and the 7 s WaitForSync at Play (CharSync.cs:71) waits for nothing. Confirm against the deployed voice-server.js. If those routes exist there, note they key on a public Steam id with no ticket, so anyone can rebind another person's slots.

16. (likely) Shell.cs:3405, 3428, 3150. Window-thread blocks past the five second "not responding" line: `Chars.WaitForSync(7000)`, the synchronous `Creation.Send` POST (5 s connect plus 5 s read), `Verify.DeployPersonal` copying every personal file on every Play with no change check, and `SkyMp.Start` sleeping up to 48 s for a local server. Run each through Waiting.

17. (likely) Uninstall.cs:398-404, 454. Begin kills the game but never calls Hold.Release or Keep.Unpark, and with keepSaves off deletes Profile, which contains Profile\Parked, so uninstalling while the game is up deletes the other server's parked plugins (moved, not copied). Fix: `Hold.Release(); Keep.Unpark();` after Kill.

18. (likely) Uninstall.cs:508, Updater.cs:662, ShellOwnGame.cs:222, DevBuild.cs:159. Batch scripts are written in ANSI or UTF-8 but cmd reads .cmd files in the OEM code page, so a user name or path with a non-ASCII character (José) garbles `rmdir`, `del`, `move` and `start`, and uninstall reports success having removed nothing. Fix: `chcp 65001 >nul` as the first line, or write in the OEM code page.

19. (verified) Pages.cs:94. In the colour line `last < 0` is tested before `last == -2`, so "Not tested yet." is painted Warn instead of Faint. Cosmetic.

20. (likely) Shell.cs:2797. `int port = 7778; int.TryParse(c.VoicePort, out port);` leaves 0 on a non-numeric value, so the voice probe hits host:0. Creation.Send parses the same value correctly. Fix: `if (port <= 0) port = 7778;`.

## Suggestions

- Server log: a gamemode-side `thornswood.log` with only Thornswood's own lines, or filtering the three noise families at the server's log level. Tonight's whole investigation was grep against 78 percent noise.
- Verify.Bytes: when a mismatch is found, name the mod in words the person knows (the plugin name is already there; adding "this is the CWE - JK - United mod from the collection" style text needs a name map, which the manifest could carry).
- Door.cs:80-86 treats an unreachable site as "yes", so blocking thornswood.net in a hosts file passes the door. Cache the last signed answer and fail closed after a grace period once the door is enforcing.
- Updater.cs:433-441 records ownership per pack, not per file: pack B writing over pack A's file records `R|`, and removing A deletes B's current file. Skip a path in RemovePack when any other pack's list, or Vortex's deployment, contains it.
- Mics.cs writes a MicrophoneName the shipped template does not carry and nothing reads, while the voice page calls getUserMedia with no deviceId, so voice uses Chromium's default microphone. Send the device in the config message and pick it by label in the page.
- Site: add og:title, og:description and og:image (links pasted in Discord unfurl with the generic home text), a Strict-Transport-Security header (the http to https 308 already works), a robots.txt, redirects for /download and /install to /downloads, and make /world#accord scroll to its anchor after the page body loads.
- Site: the "Support" links are rewritten to Patreon when /api/public carries a patreon value, which makes the /support page (tiers, character slots) unreachable from any link.
- Downgrade: the apply step and Uninstall both read only Data\vortex.deployment.json; OwnGame.DeployedIn already handles the root-level Vortex deployment files too. Use it in both.
